# Define project governance

Read and follow [the shared workflow](../../docs/workflow.md).

1. Initialize project tooling if needed. Read `.specify/memory/constitution.md`,
   existing project instructions, contributor guidance, manifests, and CI checks.
2. Ask for material missing principles: supported platforms, compatibility,
   quality gates, security/privacy constraints, review, and delivery expectations.
   Do not prescribe a language, framework, or architecture without a project reason.
3. Adapt the existing constitution in place. Preserve agreed principles and distinguish
   repository evidence, confirmed user decisions, and proposed assumptions.
4. For amendments, record the date, rationale, and affected templates or feature documents.
   Update directly dependent documents, but do not silently change another feature's scope.
5. Present the resulting principles and unresolved decisions for user review.
   Do not claim adoption or approval that the maintainer has not supplied.
